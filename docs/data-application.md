# 采集数据应用：启动、模型、口径与验证

## 当前证据（2026-10-22）

本轮开始时 Git 工作树干净，代码仍是 React + TypeScript、自定义网关 HTTP 客户端及 localStorage 有界历史。本轮新增 `edge_data/` 本地数据服务，没有覆盖现场独立服务，也没有访问现场地址来推断其是否存在。

| 能力 | 代码实现 | 本轮验证 | 现场边界 |
|---|---|---|---|
| 持续采集 | 独立 Python 线程读取网关已有 GET 接口，SQLite 存储 | 隔离 reader、线程、HTTP API、重启测试 | 真实接线与现场通信未验证 |
| 数据分析 | 原始记录查询、时间加权日报、灌溉重建与复盘 | 确定性手算、单元及浏览器测试 | 农艺目标、分析窗口和硬件反馈需实际配置 |
| 控制事件 | 可选网关只读事件接口，浏览器审计桥接 | mock 与持久化测试 | 网关无事件接口时，浏览器关闭期间的命令依据未知 |
| 真实效果 | 不提供产量、实测节水或节能结论 | 未验证 | 需连续现场采样、已确认配置与物理反馈 |

## 依赖与职责

- Python 3.11+ 标准库：`sqlite3`、`http.server`、`urllib`、`threading`，无新增 pip/npm 运行依赖。
- 继续使用 React、TypeScript 与现有原生 SVG，未引入图表库。
- 数据服务只提供采集、存储、分析和人工备注。**没有控制转发接口，不迁移确定性控制引擎，不修改阈值、寄存器、I/O 或联锁。**
- SQLite 使用 WAL、FULL 同步、事务、唯一约束和范围索引。每次数据库操作显式关闭连接；启动时执行版本迁移。适用于单机试点，不是高可用集群或工业安全控制器。

## 启动：没有现场读取的安全默认配置

```powershell
python -m edge_data --config edge-data.config.example.json
```

默认监听 `127.0.0.1:8090`，`collector_mode=disabled`，不会访问任何网关，不生成替代数据。服务运行不依赖浏览器页面；退出服务进程则停止采集。长期运行可按本机运维要求交由 Windows 任务计划或服务管理器启动，本轮没有注册系统任务或生产服务。

另一个终端启动前端（PowerShell）：

```powershell
$env:VITE_DATA_SERVICE_URL='http://127.0.0.1:8090'
node node_modules/vite/bin/vite.js --host 127.0.0.1
```

进入“数据分析”。没有数据、作物、阶段、批次或目标时会显示缺失状态，不自动套用演示阈值。端口更改时同步修改服务 `allowed_origins`；服务仅监听回环地址，不提供公网认证或多租户能力。Origin 不在允许列表的请求会被拒绝，写入仅接受有界 JSON。不要把服务直接暴露到外网。

## 可运行的隔离演示与可核对样例

```powershell
python -m edge_data --config edge_data/demo.config.json --load-test-fixture
```

这会在 `var/edge-data-demo` 存储：

- `simulation-zone`：独立持续生成的模拟采样和模拟反馈，不依赖浏览器，也不同于答辩控制台场景。
- `software-test-zone`：2026-10-20 的确定性软件样例，仅进入 simulation 分区，不是作物实测数据。

前端设置同一 `VITE_DATA_SERVICE_URL`，选择仿真分区、`software-test-zone`、自定义范围 **2026-10-20 08:00～08:10（Asia/Shanghai）**。完整日报则使用当日 24 小时分母，覆盖率与 10 分钟窗口不同。

土壤湿度样例：

| 相对秒数 | 0 | 60 | 180 | 240 | 300 | 360 | 420 | 480 |
|---|---|---|---|---|---|---|---|---|
| 值（%） | 30 | 32 | 38 | 42 | 44 | 无效 | 46 | 44 |

技术最大连接间隔 120 秒；测试目标 40～50%，仅用于软件核对，绝非推荐农艺标准。

- 有效区间：0～300 秒、420～480 秒，总计 **360 秒**；其余 **240 秒未知**，覆盖率 **60%**。
- 梯形积分：`31×60 + 35×120 + 40×60 + 43×60 + 45×60 = 13740`，时间加权均值 **38.1666667%**。
- 210 秒处线性越过 40%；目标内 **150 秒**，超限 **210 秒**，最长连续超限 **210 秒**。
- 温度与光照采用不同采样时刻，空气湿度和 CO₂ 缺失；不会填满图表或把别的指标记录误作断点。
- 第一灌溉：60 秒请求、90 秒首次运行反馈、120/150 秒同状态反馈、180 秒停止反馈。模拟反馈连续支持下界 **60 秒**；起止时长界限 **60～130 秒**。200 秒通风命令、220 秒校准记录形成重叠干预，因此不能单独归因。
- 第二灌溉：510 秒只有网关成功命令，没有运行或停止反馈。以样例时钟 650 秒分析仍在观察期；真实当前时钟超过窗口后显示无法判断。两种状态都有测试。

## 接入已有独立网关（配置准备，本轮未执行现场读取）

复制 `edge-data.config.example.json` 为已忽略的 `edge-data.config.json`，核对后设置：

```json
{
  "data_dir": "var/edge-data",
  "port": 8090,
  "collector_mode": "external",
  "gateway_base_url": "http://127.0.0.1:8080",
  "control_events_path": null,
  "poll_seconds": 5,
  "stale_after_seconds": 30,
  "max_gap_seconds": 120,
  "retention_days": 90,
  "timezone": "Asia/Shanghai",
  "sensor_zones": {},
  "device_zones": {}
}
```

地址是示例，区域映射必须依据现场资料填写，不能把 UI 中旧的逻辑位置自动当作物理位置。`sensor_zones` 以网关 `sensorId` 为键，`device_zones` 以 `waterPump/fan/growLight/shade` 为键；缺少映射及上游区域时保存为 `unassigned`，界面显示未配置。

**运行上述 external 配置前，必须由现场负责人确认 GET 接口确实只读。** 本次没有访问这些示例地址。

采集器固定使用 GET：

- `/api/v1/sensors/latest`：复用现有 schemaVersion 1 采样契约。
- `/api/v1/actuators`：复用执行器快照契约。
- 仅在显式填写 `control_events_path` 后读取该只读事件流；响应为本服务事件 DTO 数组。重复事件靠 ID 去重，乱序按事件时间复盘。不自动猜测或请求未配置的命令历史接口。

HTTP 重定向被拒绝，读取有超时与大小上限，失败后继续重试并记录采集中断，不默认水泵停机。相同数据目录有 OS 进程锁，拒绝第二个服务争抢采集；不同目录的采集者需由部署者保证不重复指向同一现场网关。

前端保持原 `VITE_EDGE_API_BASE_URL` 作为控制/AI 通道，只增加 `VITE_DATA_SERVICE_URL`。external 模式的数据通道改读本服务缓存 `/api/v1/health`、`sensors/latest`、`actuators`，**不再同时直接轮询原网关，也不会在服务故障时偷偷回退直采**。未配置数据服务时保留旧链路，但旧链路不具备独立历史存储。

离线构建强制清空数据服务地址与外部地址，始终保持无网络仿真。“分析数据分区”只改变历史查询，不改变运行模式或控制状态。

## 数据模型与隔离

存储文件分别为 `hardware.sqlite3`、`simulation.sqlite3`、`playback.sqlite3`、`unknown.sqlite3`，各有分区身份元数据，禁止跨分区恢复。上游声明 hardware 不是现场真实性认证；未声明来源进入 unknown；明确仿真/回放来源与声明冲突时隔离并标记无效。

| 数据 | 保留内容 |
|---|---|
| samples | 网关／传感器／通道／事件身份、区域、指标、原单位、值、原始与有效质量、采集/网关接收/服务接收时间、验证原因；确有提供时保存 rawValue、calibratedValue、calibrationVersion |
| events | 命令 ID、设备、区域、来源、触发原因、可获得的策略版本、目标、各阶段状态、观测时间、接收时间；反馈层级和时间精度；报警、人工操作、服务中断 |
| contexts | 不可覆盖的版本、区域、批次、作物、品种、阶段、基质、种植时间、备注、生效时间；显式确认的目标、依据及分析参数 |
| conflicts | 同一采样身份的冲突内容、接收时间；原样本保留原值但排除统计 |

采样身份由网关、传感器、指标、采集时刻确定；即使传输 eventId 改变，重复轮询也不重复计数。迟到采样可补入过去的时序；同身份的数值、单位或质量声明冲突时不覆盖原值，而是保守排除该采样。无效、错误单位和过期采样不参加分析；错误单位不做隐式换算。明确的 playback 分区按原始质量分析历史，不因回放的传输延迟再标过期，且绝不参与硬件统计或控制。校准只记录上游已有结果，本服务不生成校准系数或修改设备校准。

浏览器桥接仅向本机服务写入观测审计数据，不转发设备命令。记录失败在页面提示并重试；关闭页面可能丢失尚未送达的事件。网关未提供只读控制事件流时，不能保证页面关闭期间的命令、触发依据和策略版本完整，反馈重建仍可用。缺失字段明确保留未知，不伪造操作人。

## 时间和计算口径

- 所有时间必须含时区，统一为 UTC 毫秒计算、ISO 8601 存储。统计时区明确配置为 `Asia/Shanghai`（现代 UTC+8）或 `UTC`，避免 Windows tzdata 额外依赖；未实现任意 DST 时区。
- 每个指标/传感器使用自身时序；统计不把异步指标行当作缺失。本指标无效记录、单位错误和超过连接上限的间隔打断序列。
- 时间加权均值只在相邻有效样本、同一单位、未超过连接间隔的区间做线性插值和梯形积分；不向首末样本以外外推。查询边界可由邻近有效点夹住后裁切。
- 技术最大间隔默认 120 秒，可通过有生效时间的区域分析配置调整。它是采样连续性的工程门槛，不是作物耐受时长。
- 分母是请求窗口的实际秒数；当前日截止服务当前时刻。有效覆盖率是可积分秒数/分母，缺失是这些有效区间的补集。目标判断的未知还包括“有有效数据但没有已确认目标”。
- 目标必须关联批次、作物、阶段和依据并显式确认；区间与历史版本变化按时间分段。线性过界时间用于累计目标内/外时长，未知区间会中断最长连续超限计数。
- 最小/最大值来自范围内原始有效采样，并给出时间。变化速率来自最后一对有效、间隔合规的相邻观测，标注时间，不包装为预测。
- 没有 DLI、作物健康分、实测用水量或真实节水节能结论。

## 灌溉事件口径

- 首次开启请求建立“已请求”；仅命令成功没有运行反馈时，始终不能判为灌溉成功。
- 首次运行反馈可独立建立事件，缺少命令时原因和请求时间未知。连续运行期间的重复请求和状态反馈合并，原始反馈仍存数据库。
- 停止命令不等于停止反馈。只有实际停止反馈才闭合运行段；未知、离线、服务中断或重启不生成停止。
- 网关接受、网关状态、输出回读、物理反馈、模拟反馈分别标识。不同层级不能升级为物理确认。
- 轮询动作起止是上下界而非精确时刻；只有连续同层级反馈才计算时长界限，连续“运行”样本支持部分时长下界。中断后不强行拼接完整运行时长。
- 分析上下文取首次请求时刻，缺少请求则取首次运行反馈时刻；窗口跨配置变更会提示，目标恢复按当时版本。
- 前后窗口、湿度增量与依据默认未配置；没有配置时仅取 10/30 分钟用于展示相关记录，不据此判响应效果。
- 先计算前窗口加权湿度、近期变化与覆盖率，再寻找停止反馈后达到配置增量的首次有效采样；延迟为首次**观测**延迟，受采样间隔限制，不声称精确生理响应时间。
- 观察期未结束显示“观察中”；缺少运行/停止反馈、湿度序列、至少 80% 的前后时间覆盖，或存在重叠干预时显示“无法判断”。80% 是保守技术判读门槛，不是农艺标准。
- 未观察到预期响应只能建议核查，不能确定是缺水、泵故障或堵塞；即使观察到变化也不证明单一因果。
- 人工浇水、维护、移动、校准和其他执行器命令按区域/时间关联；可另外关联事件 ID。普通核查备注不会被当作一次物理干预。

## 查询与图表

| 接口 | 用途 |
|---|---|
| GET `/api/data/health` | 服务/采集状态、时间与分区计数 |
| GET `/api/data/zones?dataset=...` | 分区区域列表 |
| GET `/api/data/history` | 原始采样分页，包含质量/来源/校准信息 |
| GET `/api/data/report` | 基于全部原始有效数据的统计 |
| GET `/api/data/chart` | 原始或保留极值的图表序列与事件标记 |
| GET `/api/data/irrigations`、`/api/data/irrigations/:id` | 事件列表、前后环境与反馈详情 |
| GET/POST `/api/data/contexts` | 查询/追加生效版本，不覆盖已有版本 |
| POST `/api/data/notes`、`/api/data/events` | 本机人工备注与审计事件，不执行设备动作 |

范围参数：`dataset`、`zone`、`date=YYYY-MM-DD`，或带时区的 `from`/`to`。原始记录支持 `limit`（最多 5000）与 `offset`；浏览器每页 100。当前是有界 offset 分页，没有不可变多页快照；采集中补到的历史可能使分页位置移动，正式取证优先使用数据库备份。

查询最多 31 天，分析原始记录超过 200000 条时要求缩小范围，不拿降采样假装精确统计。图表约 1500 点预算，按传感器桶保留首末、极值、全部无效点和事件附近数据；为保留断点可能超出预算。控制标记超过 2000 时提示缩小范围。统计与图表明确分开。

图表采用真实时间轴和每序列独立数值轴、单位、精确采样查看；不让不同量纲的缩放斜率看起来可直接比较。支持查看灌溉、通风、报警、人工操作及采集中断标记。大窗口可改用自定义时间范围复盘。

## 保留、迁移、备份和恢复

- 迁移：`edge_data/migrations/001_initial.sql`，启动时事务执行，`PRAGMA user_version=1`；遇到更高版本拒绝打开，不做破坏性降级。
- 默认保留 90 天，每小时清理过期采样、事件和冲突；不删除历史上下文版本，以便解释保留样本。数据库清理不自动 VACUUM，不删除备份。超过保留期的灌溉起点可能未知。
- `var/` 与所有 SQLite/WAL 文件已忽略，不提交业务数据或密钥。
- 使用 SQLite 在线 backup API，包含已提交 WAL 内容并运行完整性检查。目标已存在时拒绝覆盖。

```powershell
python -m edge_data --data-dir var/edge-data --backup var/backups/hardware-2026-10-22.sqlite3 --dataset hardware
python -m edge_data --data-dir var/edge-data --backup var/backups/simulation-2026-10-22.sqlite3 --dataset simulation
```

建议按需要备份各分区，并把备份复制到另一个受控存储位置。本轮未创建系统级定时备份任务；单机文件不是异地容灾。

恢复到**新的数据目录**，不要覆盖正在运行的数据库：

```powershell
python -m edge_data --data-dir var/edge-data-restored --restore var/backups/hardware-2026-10-22.sqlite3 --dataset hardware
```

恢复会检查完整性、版本及分区身份；随后将运行配置的 `data_dir` 指向恢复目录再启动。不得只复制活跃的 `.sqlite3` 而漏掉 WAL，也不要手工删除现有库来“重试”。
